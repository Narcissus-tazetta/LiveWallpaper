# Store 統合テスト

リポジトリのルートから実行する。

```sh
cd store-worker && bun install
cd ..
./scripts/test_store_integration.sh
```

macOS、Swift/Xcode、Bun が必要。ローカルWorkerは空いているループバックポートで起動し、DBとR2のデータは一時ディレクトリへ保存する。終了時にプロセスとデータを片付ける。本番の接続情報や `.dev.vars` は使用しない。

型チェック、Workerの既存テスト、Swiftとの統合テストの順に実行する。いずれかが失敗すると非ゼロの終了コードを返す。

実際のSwiftクライアントとWorkerで、シーンの投稿、サムネイル送信、承認前の非公開状態、管理者による承認、カタログ取得、ダウンロード、チェックサム検証、シーンと素材の取り込み、動画の再生可能性を検証する。未完了のシーン編集を含む投稿を対象にする。不正な管理者キーやチェックサムも検証する。

Workerの互換日付・互換フラグ・レート制限は `wrangler.toml` から読み込む。R2アップロードは、本番Workerが生成した署名URLをテスト用アダプターでローカルへ転送し、署名・サイズ・Content-Typeを確認して隔離したR2へ保存する。メール送信はローカルで受け取る。アプリ側とWorker側の外部通信は拒否する。

署名の検証も同じライブラリを使用するため、Cloudflare R2側の署名受け入れ、権限、CORS、メール配信そのものはこのテストでは保証しない。テスト用ルートは本番Workerのエントリーポイントに含まれない。

通常の `swift test` ではWorkerが起動していないため、この統合テストは実行方法を表示してスキップする。
